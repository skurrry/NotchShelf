# Contributing to NotchShelf

Issues and pull requests are welcome.

## Issues

Before opening an issue, check whether a similar report already exists. Bug reports should include:

- macOS version
- Xcode version for build problems
- reproduction steps
- expected behavior
- actual behavior
- screenshots or logs when useful

## Pull requests

A pull request proposes changes from your branch to the main project.

1. Fork the repository.
2. Create a focused branch such as `fix/shelf-drag`.
3. Implement and test one clearly scoped change.
4. Commit the change.
5. Push the branch.
6. Open a pull request with test notes and screenshots when relevant.

## Project expectations

- Do not unintentionally remove confirmed core behavior.
- Prefer native Apple APIs.
- Consider Dark Mode, VoiceOver, keyboard use, and Reduce Motion.
- Never commit secrets, certificates, Team IDs, provisioning profiles, or personal paths.
- Discuss large architectural changes in an issue first.
